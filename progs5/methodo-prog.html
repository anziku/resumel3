      Prouver une boucle : variant et invariant

      Variant → terminaisonUne expression entière, ≥ 0, qui décroît strictement à chaque tour. Pour la division : Reste. Pour une recherche : Taille - I + 1. Pour le PGCD par soustractions : na + nb. Un Pour termine toujours.
      Invariant → correctionPropriété vraie avant la boucle et après chaque tour. Pour la division : Dividende = Diviseur * Quotient + Reste. À la sortie : invariant ET non condition = post-condition.

      CH. 3 · poly D · le cœur de l'examen

      La méthode des raffinages

      Diviser pour régner : on décompose une action trop complexe en sous-actions plus simples, jusqu'à n'avoir que des instructions. C'est 40 % de la note, et c'est ce qui distingue ce cours de « savoir coder ».

      Les quatre étapes, à appliquer à chaque action complexe

      1. Comprendre le problème (QUOI ?)
        Reformuler en une phrase : le R0, verbe à l'infinitif. Puis donner des exemples : entrées ET résultats attendus, un cas nominal, des cas limites, des cas d'erreur. Ce sont tes futurs tests.
      2. Trouver une solution informelle (COMMENT ?)
        L'idée en français, sans structure. La faire tourner à la main sur les exemples.
      3. Structurer la solution
        Lister les étapes, les ordonner, les regrouper, écrire les flots de données, choisir les structures de contrôle, puis raffiner les actions encore complexes (R1 → R2 → … → Rn). On commence par l'action la moins bien comprise.
      4. Produire l'algorithme
        Mise à plat de l'arbre : les nœuds deviennent des commentaires, les feuilles des instructions, les flots de données donnent les variables. Puis tester avec les exemples de l'étape 1.

with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;

-- Afficher le pgcd de deux entiers strictement positifs.
procedure Afficher_Pgcd is
   A, B   : Integer;  -- les deux entiers saisis
   Na, Nb : Integer;  -- copies de travail de A et B
   Pgcd   : Integer;  -- le pgcd de A et B
begin
   -- Demander deux entiers a et b
   loop
      Put ("a et b (> 0) ? ");
      Get (A);
      Get (B);
      Skip_Line;
      exit when A > 0 and B > 0;
   end loop;

   -- Déterminer le pgcd de a et b
   Na := A;
   Nb := B;
   while Na /= Nb loop   -- variant : Na + Nb
      -- Soustraire au plus grand le plus petit
      if Na > Nb then
         Na := Na - Nb;
      else
         Nb := Nb - Na;
      end if;
   end loop;
   Pgcd := Na;

   -- Afficher le pgcd
   Put ("pgcd = ");
   Put (Pgcd, 1);
   New_Line;
end Afficher_Pgcd;

      Règles de qualité d'un raffinage

      • Toujours commencer par R0 + exemples.
      • Une action complexe = verbe à l'infinitif + complément précis.
      • Préférer Déterminer, Calculer à Comparer, Vérifier (qui ne disent pas ce qu'on produit).
      • Structures de contrôle explicites : pas de « si » caché dans une phrase.
      • Un raffinage décrit complètement son action, et seulement elle.
      • Pas d'action qui paraphrase une seule instruction (« Incrémenter I »).
      • Plus de 5–6 actions ou plusieurs boucles dans un même raffinage : il manque un niveau.
      • Un raffinage n'apparaît jamais avant l'action qu'il décompose.
      Le test Comment / PourquoiLe raffinage de C répond à « Comment C ? ». À l'envers, pour chaque sous-action A, « Pourquoi A ? » doit répondre C. Si ça coince : renommer A ou C, ajouter une action intermédiaire, ou A n'est pas à sa place.

      Une action du raffinage qui revient, ou qui mérite un nom, devient un sous-programme. Ses flots de données deviennent ses paramètres. Son R0 devient son contrat.

      Le contrat, au-dessus de chaque sous-programme

      -- Nom : Permuter
-- Sémantique : permuter les valeurs de deux variables
-- Paramètres :
--    F_X : in out Réel   -- première variable
--    F_Y : in out Réel   -- seconde variable
-- Pré-condition : Vrai
-- Post-condition : F_X = F_Y'Avant Et F_Y = F_X'Avant
-- Exceptions : aucune
-- Tests :
--    F_X = 3, F_Y = -5  ==>  F_X = -5, F_Y = 3
PROCÉDURE Permuter (F_X : in out Réel; F_Y : in out Réel) EST
   Mémoire : Réel     -- valeur de F_X avant modification
DÉBUT
   Mémoire <- F_X
   F_X <- F_Y
   F_Y <- Mémoire
FIN Permuter
      -- Permuter les valeurs de deux variables.
procedure Permuter (X : in out Float; Y : in out Float) with
   Post => X = Y'Old and Y = X'Old
is
   Memoire : Float;  -- valeur de X avant modification
begin
   Memoire := X;
   X := Y;
   Y := Memoire;
end Permuter;

-- Pgcd de deux entiers strictement positifs.
function Pgcd (A, B : in Integer) return Integer with
   Pre  => A > 0 and B > 0,
   Post => Pgcd'Result > 0 and A mod Pgcd'Result = 0
                            and B mod Pgcd'Result = 0;

      Notations : X'Avant en algo, X'Old en Ada ; F'Result est le résultat d'une fonction dans sa post. Paramètres formels préfixés F_ (convention du cours).

      Qui garantit quoi ?

      Obligation deBénéfice pour

      Paramètres : les cinq règles qui font les exercices « Trouver les erreurs »

      1. Autant de paramètres effectifs que de formels, même type à chaque position.
      2. Formel in → l'effectif peut être n'importe quelle expression : G (P, 3 + M).
      3. Formel out ou in out → l'effectif doit être une variable : F (Y * Y) est faux.
      4. Un paramètre in ne peut pas être modifié dans le corps.
      5. Un appel de procédure est une instruction, il n'a pas de valeur : Y := G (Y, M) et G (Y, F (M)) sont faux si F et G sont des procédures.

      Appel nommé possible : Permuter (F_Y => Ordonnee, F_X => Abscisse);. Mode à choisir selon le flot réel, jamais in out « par sécurité ».

      Surcharge et récursivité

      Surcharge : plusieurs sous-programmes de même nom, distingués par le nombre ou le type des paramètres (Put pour Integer, Float, Character…).

      -- Pré-condition : F_N >= 0
FONCTION Factorielle (F_N : in Entier) RETOURNE Entier EST
DÉBUT
   Si F_N = 0 Alors
      RETOURNE 1                          -- cas de base
   Sinon
      RETOURNE F_N * Factorielle(F_N - 1) -- cas récursif
   FinSi
FIN Factorielle
      function Factorielle (N : in Integer) return Integer with
   Pre => N >= 0
is
begin
   if N = 0 then
      return 1;                       -- cas de base
   else
      return N * Factorielle (N - 1); -- cas récursif
   end if;
end Factorielle;

Terminaison : un paramètre entier ≥ 0 qui décroît strictement à chaque appel (ici N). Chaque appel empile un contexte : récursion trop profonde → Storage_Error.

      Exceptions : qui reprend la main ?

      L'exercice « Exemple_Exception » est tombé à l'identique en 2021, 2023 et 2024. Il suffit de connaître une règle de propagation.

      Pile_Vide : exception;            -- déclarer
raise Pile_Vide;                  -- lever
begin                             -- traiter, dans n'importe quel bloc
   ...
exception
   when Constraint_Error => Put_Line ("Hors bornes");
   when E1 | E2 => ...
   when others => ...
end;

      La règle de propagation

      1. Une exception est levée : le bloc courant s'arrête immédiatement et définitivement. Les instructions suivantes du bloc ne sont pas exécutées.
      2. On cherche un when correspondant dans la partie exception de ce bloc.
      3. Trouvé : le traitement s'exécute, puis l'exécution reprend après le bloc (ou, si c'est le corps d'un sous-programme, juste après l'appel, chez l'appelant).
      4. Pas trouvé : l'exception remonte au bloc englobant ou à l'appelant, et on recommence en 2. Arrivée au programme principal sans traitement : le programme s'arrête en affichant le nom de l'exception.

        Élément majoritaire · 2019, 2021, 2022, 2023 · 7 pts

        x est majoritaire dans T[1..Taille] si son nombre d'occurrences est strictement supérieur à Taille / 2. S'il existe, il est unique. Exemple : 6 1 6 6 3 6 8 6 6 7 → 6 (6 fois > 5).

        Contrat et entêteQ1
        -- Nom : Majoritaire
-- Sémantique : déterminer si F_T contient un élément majoritaire et, si oui, lequel
-- Paramètres :
--    F_T      : in T_Tab      -- le tableau étudié
--    F_Existe : out Booléen   -- VRAI ssi un élément majoritaire existe
--    F_Elt    : out Entier    -- l'élément majoritaire (si F_Existe)
-- Pré-condition : 0 <= F_T.Taille <= CAPACITE
-- Post-condition : F_Existe = (il existe x tel que Nb_Occ(F_T, x) > F_T.Taille Div 2)
--                  Et (F_Existe ⇒ Nb_Occ(F_T, F_Elt) > F_T.Taille Div 2)
-- Tests :
--    6 1 6 6 3 6 8 6 6 7  ==> F_Existe = VRAI, F_Elt = 6   -- nominal
--    6 1 6 7 3 5 8 4 2 7  ==> F_Existe = FAUX              -- pas de majoritaire
--    4 4 5 5              ==> F_Existe = FAUX              -- limite : exactement la moitié
--    9                    ==> F_Existe = VRAI, F_Elt = 9   -- un seul élément
--    (vide)               ==> F_Existe = FAUX              -- tableau vide
PROCÉDURE Majoritaire (F_T : in T_Tab; F_Existe : out Booléen; F_Elt : out Entier)

        Deux résultats → procédure avec deux out. Une fonction ne peut pas convenir : elle n'a que des paramètres in et ne retourne qu'une valeur.

        PROCÉDURE Majoritaire (F_T : in T_Tab; F_Existe : out Booléen; F_Elt : out Entier) EST
   I : Entier        -- indice du candidat courant
   Nb_Occ : Entier   -- nombre d'occurrences du candidat dans F_T
DÉBUT
   F_Existe <- FAUX
   I <- 1
   TantQue Non F_Existe EtAlors I <= F_T.Taille Faire   -- variant : F_T.Taille - I + 1
      -- Compter les occurrences de F_T.Elements(I)
      Nb_Occ <- 0
      Pour J De 1 À F_T.Taille Faire
         Si F_T.Elements(J) = F_T.Elements(I) Alors
            Nb_Occ <- Nb_Occ + 1
         FinSi
      FinPour
      -- Mémoriser le candidat s'il est majoritaire
      Si Nb_Occ > F_T.Taille Div 2 Alors

         F_Elt <- F_T.Elements(I)
      Sinon
         I <- I + 1
      FinSi

        Drapeau hollandais · 2019, 2022 · 7 pts

        Réorganiser T en trois zones autour du pivot V : < V | = V | > V, dans le même tableau. Exemple V = 6 : 6 1 9 8 3 6 8 9 5 7 → 5 1 3 6 6 8 9 8 9 7 (l'ordre dans chaque zone est libre).

        Contrat, invariant à trois indices, algorithmecorrigé
        -- Sémantique : réorganiser F_T en zones < F_V, = F_V, > F_V
-- Paramètres : F_T : in out T_Tab ; F_V : in Entier (le pivot)
-- Pré : 0 <= F_T.Taille <= CAPACITE
-- Post : F_T.Taille = F_T.Taille'Avant, F_T contient les mêmes éléments qu'avant,
--        et il existe I, J tels que T[1..I-1] < F_V, T[I..J] = F_V, T[J+1..Taille] > F_V
PROCÉDURE Drapeau (F_T : in out T_Tab; F_V : in Entier)

        L'idée (Dijkstra) : trois indices délimitent quatre zones pendant le parcours.

        1 Inf Cour Sup Taille [ < V | = V | non traités | > V ] invariant : T[1..Inf-1] < V, T[Inf..Cour-1] = V, T[Sup+1..Taille] > V variant : Sup - Cour + 1 (la zone non traitée rétrécit à chaque tour)
        PROCÉDURE Drapeau (F_T : in out T_Tab; F_V : in Entier) EST
   Inf : Entier    -- début de la zone = V
   Cour : Entier   -- prochain élément à traiter
   Sup : Entier    -- fin de la zone non traitée
DÉBUT
   Inf <- 1
   Cour <- 1
   Sup <- F_T.Taille
   TantQue Cour <= Sup Faire
      -- Ranger F_T.Elements(Cour) dans sa zone
      Si F_T.Elements(Cour) < F_V Alors
         Permuter(F_T.Elements(Inf), F_T.Elements(Cour))
         Inf <- Inf + 1
         Cour <- Cour + 1
      SinonSi F_T.Elements(Cour) = F_V Alors
         Cour <- Cour + 1
      Sinon
         Permuter(F_T.Elements(Cour), F_T.Elements(Sup))
         Sup <- Sup - 1        -- Cour ne bouge pas : l'élément reçu n'est pas traité
      FinSi
   FinTQ
   { Cour = Sup + 1 : la zone non traitée est vide }
FIN Drapeau

        Trace sur l'exemple : on obtient 1 5 3 | 6 6 | 8 9 8 7 9. Une seule passe, O(n), aucun tableau auxiliaire, comme l'exige l'énoncé.

        Codage de Vigenère · 2017, 2022 · 6 pts

        Chaque lettre est décalée du code de la lettre de clé correspondante (A = 0 … Z = 25). La clé est répétée ; les espaces restent des espaces et ne consomment pas de lettre de clé. ELEVE DE … + BONJO UR … → FZRES XV…

        Contrat et algorithmecorrigé
        -- Sémantique : coder F_Msg par la méthode de Vigenère avec la clé F_Cle
-- Paramètres :
--    F_Msg : in T_CHAINE ; F_Lg_Msg : in Entier    -- message et sa longueur
--    F_Cle : in T_CHAINE ; F_Lg_Cle : in Entier    -- clé et sa longueur
--    F_Code : out T_CHAINE                         -- message codé (longueur F_Lg_Msg)
-- Pré : 0 <= F_Lg_Msg <= Longueur_Max Et 1 <= F_Lg_Cle <= Longueur_Max
--       Et F_Msg[1..F_Lg_Msg] ne contient que 'A'..'Z' et ' '
--       Et F_Cle[1..F_Lg_Cle] ne contient que 'A'..'Z'
-- Post : pour tout I, F_Code(I) = ' ' si F_Msg(I) = ' ', sinon la lettre de code
--        (code(F_Msg(I)) + code(lettre de clé associée)) Mod 26
-- Test : "ELEVE DE PREMIERE ANNEE", "BONJOUR" ==> "FZRES XVQFR VWYIF OAWSY"
PROCÉDURE Vigenere (F_Msg : in T_CHAINE; F_Lg_Msg : in Entier;
                    F_Cle : in T_CHAINE; F_Lg_Cle : in Entier;
                    F_Code : out T_CHAINE) EST
   J : Entier          -- indice dans la clé de la prochaine lettre à utiliser
   Decalage : Entier   -- somme des codes de la lettre et de la lettre de clé
DÉBUT
   J <- 1
   Pour I De 1 À F_Lg_Msg Faire
      Si F_Msg(I) = ' ' Alors
         F_Code(I) <- ' '
      Sinon
         -- Coder la lettre F_Msg(I) avec la lettre de clé F_Cle(J)
         Decalage <- (Ord(F_Msg(I)) - Ord('A')) + (Ord(F_Cle(J)) - Ord('A'))
         F_Code(I) <- Chr(Ord('A') + Decalage Mod 26)
         -- Passer à la lettre de clé suivante (circulairement)
         J <- J Mod F_Lg_Cle + 1
      FinSi
   FinPour
FIN Vigenere

        Vérification : E(4) + B(1) = 5 → F ; L(11) + O(14) = 25 → Z ; V(21) + J(9) = 30 mod 26 = 4 → E. Le type T_CHAINE n'a pas de longueur : il faut la passer en paramètre, ou mieux définir un enregistrement (chaîne + longueur), ce qu'on peut proposer en copie.

        Plus longue séquence triée · 2024 · 8 pts

        6 1 9 8 3 6 8 9 5 7 → 3 6 8 9. À égalité de longueur, n'importe laquelle.

        Contrat et algorithme en une passecorrigé
        -- Sémantique : extraire de F_T sa plus longue suite de cases consécutives triée
-- Paramètres : F_T : in T_Tab ; F_Seq : out T_Tab
-- Pré : 0 <= F_T.Taille <= CAPACITE
-- Post : F_Seq est triée, c'est une tranche de F_T, et aucune tranche triée
--        de F_T n'est plus longue que F_Seq.Taille
-- Tests : 6 1 9 8 3 6 8 9 5 7 ==> 3 6 8 9 ; 5 4 3 ==> 5 ; 1 2 3 ==> 1 2 3 ; vide ==> vide
PROCÉDURE Sequence (F_T : in T_Tab; F_Seq : out T_Tab) EST
   Debut_Cour : Entier      -- début de la séquence triée en cours
   Meilleur_Debut : Entier  -- début de la plus longue séquence trouvée
   Meilleure_Long : Entier  -- sa longueur
DÉBUT
   -- Déterminer la plus longue séquence triée
   Debut_Cour <- 1
   Meilleur_Debut <- 1
   Si F_T.Taille = 0 Alors
      Meilleure_Long <- 0
   Sinon
      Meilleure_Long <- 1
   FinSi
   Pour I De 2 À F_T.Taille Faire
      Si F_T.Elements(I) < F_T.Elements(I - 1) Alors
         Debut_Cour <- I                     -- la séquence est rompue
      FinSi
      Si I - Debut_Cour + 1 > Meilleure_Long Alors
         Meilleur_Debut <- Debut_Cour
         Meilleure_Long <- I - Debut_Cour + 1
      FinSi
   FinPour
   -- Copier cette séquence dans F_Seq
   Pour K De 1 À Meilleure_Long Faire
      F_Seq.Elements(K) <- F_T.Elements(Meilleur_Debut + K - 1)
   FinPour
   F_Seq.Taille <- Meilleure_Long
FIN Sequence

        Qu'appelle-t-on « action complexe » dans la méthode des raffinages ?2021 · 23 · 24

        Une action que le processeur ne sait pas exécuter directement : elle n'est pas une instruction élémentaire du langage. Elle s'écrit comme un verbe à l'infinitif (« Calculer le pgcd de a et b ») et doit être raffinée, décomposée en sous-actions plus simples, jusqu'à n'obtenir que des instructions. Dans l'algorithme final, elle devient le commentaire qui précède son bloc d'instructions.

        Expliquer les « flots de données ». Quel est leur intérêt ?2021 · 23 · 24

        Pour chaque action d'un raffinage, on indique les données qu'elle utilise (in), produit (out) ou modifie (in out). Intérêt : vérifier que chaque donnée est produite avant d'être utilisée et que les sous-actions produisent bien les sorties de l'action mère ; identifier les variables de l'algorithme ; et, si l'action devient un sous-programme, donner directement ses paramètres et leurs modes.

        Qu'est-ce qu'un module générique ? Quel est son intérêt ?2019 → 2024

        Un module paramétré par des types, des constantes ou des sous-programmes (partie generic). Il n'est pas utilisable directement : on l'instancie avec des paramètres effectifs (package Piles_Entiers is new Piles (Integer);). Intérêt : écrire et tester une seule fois un algorithme ou une structure (pile, liste, tri) valable pour tous les types, sans dupliquer le code, en gardant le contrôle de type à la compilation.

        Comparer programmation offensive et défensive.tous les ans

        Offensive : on fait confiance à l'appelant ; les cas d'erreur sont exclus par la précondition, que l'appelant doit vérifier. Code simple et rapide, mais comportement indéfini si le contrat n'est pas respecté. Défensive : le sous-programme vérifie lui-même ses données (précondition souvent Vrai) et signale l'erreur, en général en levant une exception. Plus robuste, mais un test à chaque appel. Exemple : Depiler avec pré « pile non vide » (offensif) ou qui lève Pile_Vide (défensif).

        À quoi sert une précondition ? Une postcondition ?tous les ans

        Elles forment le contrat d'un sous-programme. La précondition est la condition que l'appelant doit garantir avant l'appel (ex. N >= 0 pour Factorielle) ; le sous-programme n'a pas à la tester. La postcondition est ce que le sous-programme garantit à la fin si la précondition était vraie (ex. Résultat = N!). Elles servent à spécifier sans montrer le code, à raisonner sur la correction, à écrire les tests, et en Ada (Pre, Post, option -gnata) à détecter les erreurs à l'exécution et à savoir qui est fautif.

        Liens entre raffinages et sous-programmes ? Et architecture ?2019 · 2020

        Oui. Une action complexe d'un raffinage (surtout si elle est réutilisée) devient un sous-programme : son intitulé donne la sémantique, ses flots de données les paramètres et leurs modes, ses assertions la pré et la post. Inversement, le corps d'un sous-programme se conçoit par raffinages à partir de sa spécification (R0). L'architecture logicielle organise ensuite ces sous-programmes en modules et représente les liens « appelle », « utilise », « réalise », « instancie » entre eux.

        Spécification vs implantation d'un module ? Avantages d'un module ?2018 S2

        La spécification (.ads) est l'interface visible des clients : types, constantes, signatures et contrats des sous-programmes, avec une partie private pour la représentation. L'implantation (.adb) contient le code de ces sous-programmes et les éléments internes. Avantages : encapsulation, masquage de l'information (invariants protégés), changement d'implantation sans impact sur les clients, réutilisation, compilation séparée, travail en équipe.

        Lien entre appelant et appelé ? Que signifie une précondition Pre_1 sur SP1 ?2018 S2

        Ils sont liés par le contrat et les paramètres : l'appelant fournit des paramètres effectifs compatibles (nombre, types, modes) et garantit la précondition ; l'appelé garantit la postcondition. Définir Pre_1 sur SP1 signifie que tout appelant doit s'assurer que Pre_1 est vraie avant d'appeler SP1 ; SP1 peut la supposer vraie sans la tester. Si elle est fausse, l'erreur est chez l'appelant.

        Signature d'un sous-programme ? Intérêt des types énumérés ?2018

        Signature : son nom, la liste de ses paramètres formels (nom, mode, type) et, pour une fonction, son type de retour. C'est ce qui permet de vérifier un appel (et de distinguer des sous-programmes surchargés). Énumérés : nommer explicitement un ensemble fini de valeurs (jours, directions) ; programme plus lisible qu'avec des entiers codés, valeurs invalides refusées par le compilateur, case exhaustif vérifié, attributs Succ, Pred, Pos, Image disponibles.

        Les structures de répétition et quand les utiliser ?2018 S2

        Pour : nombre de tours connu à l'avance (parcours complet d'un tableau). TantQue : nombre inconnu, éventuellement zéro tour (recherche, lecture jusqu'à une sentinelle). Répéter … JusquÀ : au moins un tour (saisie contrôlée, menu). Pour TantQue et Répéter, la séquence doit modifier la condition et on justifie la terminaison par un variant.
